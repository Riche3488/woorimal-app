## 저장과 보상

학습 결과는 최초 판정 때 한 번 기록하고, 퀴즈 낱알·완료 횟수는 마지막 피드백을 넘겨 완료할 때 확정한다. 저장에 실패하면 다음 문제로 진행하지 않으며 재시도는 같은 결과를 다시 집계하지 않는다. 뒤로 가기는 정지 후 홈으로 이동하고, 명시적으로 판을 끝내도 이미 푼 문제의 기록은 남긴다.

새 퀴즈는 `learning-v2` 정책으로 기본 정답 10낱알, 처음 푼 문항 +5, 예정 복습 +5를 사용한다. 속도와 연속 정답 배수는 적용하지 않는다. 퍼즐은 직접 해결 5·초성 도움 3낱알을 유지한다. 같은 항목의 당일 반복 보상은 막고, 시작한 판의 정책 버전은 복구 후에도 유지한다.

기존 기록의 낱알·레벨·복습·별·퍼즐은 유지한다. 업데이트 당일 이미 한 학습으로 목표를 달성 상태로 이월할 수 있지만, 실제 학습한 항목 수를 임의로 5개로 만들어 표시하지 않는다. 발견은 정답 낱말로 합치고, 퀴즈의 유효 학습 개수와 서로 다른 낱말 수를 구분한다.

## 기기 검증

임시 읽기 전용 Android 에뮬레이터와 Expo Go에서 개발 서버의 Android 묶음을 실행했다. 기존 학습 기록의 목표 이월, 5문제 퀵플레이의 보기형·하트/시간 없음, 정답 수동 피드백과 +15낱알·별 저장 표시를 확인했다. 프로젝트 밖 공유 의존성은 작업 디렉터리의 junction과 Metro watchFolders로 연결했다. 일반 설치의 node_modules 경로에는 기본 설정을 유지한다.

정답 해설에서 홈으로 나간 뒤 Expo Go 프로세스를 종료·재실행했다. 홈의 `이어 하기 · 1/5`에서 명시적으로 재개했을 때 같은 문제·별·`+15`가 복구됐다. 나머지 문제를 마치자 `5/5`, `+75`, 레벨 상승과 장식 해제가 표시됐다. 종료 전 낱알은 기존 133개였고, 완료 뒤 208개가 됐다.

개발용 정답 제출 기능을 이용한 검사이며 production 배포나 실제 사용자 성과 측정을 뜻하지 않는다. 한글 키보드별 입력, TalkBack 전체 흐름, 저장 지연의 실기기 부하, 여러 날 알림 전달은 아직 확인하지 않았다. 백그라운드 30분 뒤에도 기존 잔여 15초가 유지되는 경우는 화면 자동 테스트로 확인했다.

## 구현 중 조정한 사항

- 기존 main과 미추적 사용자 파일을 보존하기 위해 전용 worktree를 사용했다. Jest의 scratch 제외 경로를 저장소 루트 기준으로 고쳐 작업 디렉터리 전체가 테스트에서 빠지는 문제를 막았다.
- 최근 결과는 동결한 세션과 보상 요약 한 개, 최근 완료 식별자 30개로 보관한다. 같은 문제 본문을 영수증마다 중복 저장하지 않는다.
- 저장·피드백을 하나의 세션 제어기로 연결했고, 복구와 피드백 화면의 구현/검증을 함께 진행했다. 보호된 Git index 접근이 필요한 작업 단위 커밋은 릴리스 묶음으로 정리했다.
- 과거 목표의 달성 상태를 유지하되 학습 개수를 조작하지 않는다. 개인화는 기본 활성화 대신 개발/preview의 명시적 실험으로 둔다.
- 콘텐츠 검사와 파일은 준비했으나 국어 검수 완료를 대신하지 않는다. [검수 절차](content/spacing-explanation-review.md)와 [20문항 원본 검수 파일](content/spacing-review-pilot.json)을 사용한다.

후속 범위는 [탐험 지도](superpowers/specs/player-adventure-map.md)와 [주간 도전/공유](superpowers/specs/weekly-challenge-sharing.md)에 정리했다. 계정·친구 목록·자동 순위표는 현재 앱에 추가하지 않았다.

## 독립 리뷰와 수정

`bc8db4f..f2fa66c` 전체 변경을 독립 검토했다. 주요 문제 7건과 저장 경계의 빈 문자열 분류를 수정하고, 각 재현 테스트가 수정 전 실패·수정 후 통과함을 확인했다. 최종 회귀 검사는 50개 묶음·315개 테스트 통과, 타입 검사 통과다. 이 수정 뒤 Android 기기 검사를 다시 수행하지는 않았다.

| 두 별 담기 저장이 연속 실패 | 미확정 작업을 순서대로 보관해 한 번의 재시도로 모두 저장한다. |
| 카드·퍼즐 저장 지연·실패 | 기록·보상 확정 표시는 저장 확인 뒤 보여 준다. 실패하면 입력과 동일한 제출을 재시도할 수 있다. |

작은 후속 문제 두 항목은 남겼다. 날짜를 과거로 돌리면 홈의 일일 도전 표시와 시작 판정이 다를 수 있고, 홈 공유에는 결과 화면과 같은 묶음·규칙 식별자가 아직 없다. 진단에는 저장 실패·결과의 다음 선택·도움 재시도 이벤트가 일부 빠져 있으므로 관련 분석을 완전한 수치로 산출할 수 없다.

콘텐츠 국어 검수, 여러 날·재부팅 후 알림 전달, 실기기 키보드·TalkBack·큰 글꼴·느린 저장, 참여자 만족도·D1/D7·개인화 효과, production 배포와 지도·주간·소셜 구현은 이번 독립 코드 리뷰가 확인한 범위에 포함되지 않는다.

## 판단과 남은 비용

- 전용 worktree에 구현했다. 통합·실행 시 기능 브랜치를 선택해야 한다.
- Jest 제외 경로를 저장소 루트 기준으로 고쳤다. 임시 파일 탐색 범위가 달라지므로 전체 테스트 수로 누락을 확인했다.
- Task 8은 검사·미검수 20문항 준비까지다. 원본 국어 검수가 끝나기 전까지 해설 568개의 공백이 남는다.
- 저장과 피드백 작업을 함께 연결하고 릴리스 단위로 커밋했다. 개별 UI 변경의 커밋 분리는 덜 세밀하지만 집중 테스트로 확인했다.
- 전체 결과는 최근 한 개, 완료 식별자는 최근 30개를 보관한다. 이전 여러 판의 상세 결과를 모두 다시 열 수는 없다.
- 집중 검사는 정확한 파일 경로로 실행했다. 관련 없는 테스트는 전체 회귀 검사에서 확인했다.
- 국어 정확성과 원본 발행은 미완료 범위로 유지한다. 이 상태로 배포하면 해설이 부족한 문항은 남는다.
- 알림은 반복 예약·탭 처리까지만 확인했다. 여러 날 전달을 보장하는 검사는 기기별로 필요하다.
- 키보드·접근성·저장 부하는 추가 기기 검증 대상으로 둔다. 자동 검사로 기기 조작성을 확정하지 않는다.
- 유지율과 개인화 효과를 확정하지 않고 개인화는 기본 꺼짐으로 둔다. 효과 판단에는 참여자 관찰이 필요하다.
- 지도·주간 도전·소셜·production 배포는 후속 범위다. 기능 브랜치와 초안 PR만으로 서비스에 반영되지 않는다.
