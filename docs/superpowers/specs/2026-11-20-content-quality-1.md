# 해설 채우기 · 같은 낱말 막기 · 보기로 풀기 · 문제 신고

작성일: 2026-11-20 · 근거: [콘텐츠 확장·경험 개선 방안](../../2026-11-20-content-expansion-ideas.md)의 1~2단계(C1·C2·C3·E5)

## 목적

- 틀린 뒤 정답만 보고 지나가지 않게 한다(해설 없는 문제 4,221개 → 570개).
- 한 판에 같은 낱말이 첫소리·뜻 두 번 나오지 않게 한다.
- 지하철에서 한 손으로도 풀 수 있게, 입력형을 보기로 풀 수 있게 한다.
- 잘못된 문제를 알릴 길을 둔다.

## 웹 저장소(`woorimal_contest`)

`scripts/lib/app-explain.mjs`의 `explainFiller`를 `buildAppPack`이 모든 문제에 적용한다. 형식 변경 없음(`explain` 문자열 그대로).

| 유형 | 채우는 해설 |
| --- | --- |
| 뜻·첫소리 | `낱말 · 품사 · 어원` + `예: 예문`. 해설이 예문뿐이던 문제도 이 형식으로 다시 만든다 |
| 속담 | 빈칸을 채운 온전한 문장 + 빈칸 낱말의 사전 뜻 |
| 맞춤법 | `바른 표기: …` / `틀린 표기: …` |
| 띄어쓰기 | 건드리지 않음(규칙 설명은 사람이 쓴다. 남은 568개) |

사전의 다른 풀이("다른 뜻")는 넣지 않는다. 표제어 번호가 없어 소리만 같은 다른 낱말(배려 → 背戾 "배반되고 어그러짐")이 섞이기 때문이다.

## 앱

- **같은 낱말 한 번만**(`picker.ts`의 `distinctAnswers`, `challenge.ts`): 일반·복습·⭐·유형 연습·오늘의 문제 모두, 정답을 `normalizeAnswer`로 맞춰 한 판에 한 번만 낸다. 복습할 문제가 먼저 자리를 잡는다. 오늘의 문제 구성은 이 앱 버전부터 달라질 수 있다.
- **보기로 풀기**(`choices.ts`, 설정 `choiceMode`, 기본 꺼짐): 입력형(뜻·첫소리·속담)을 보기 4개로 바꾼다. 오답 보기는 같은 갈래(낱말끼리, 속담끼리)의 다른 정답에서 초성이 같은 것 → 글자 수가 같은 것 → 첫 초성이 같은 것 순으로 고르고, 같은 뜻풀이를 가진 낱말·동의어는 뺀다. 오늘의 문제는 모두에게 같아야 하므로 바꾸지 않는다. 내장 묶음의 입력형 5,125개 전부가 바뀌는지 테스트한다.
- **문제 신고**(`report.ts`, 게임 해설 화면의 "문제가 이상해요"): 웹 제보 화면 `report.html?kind=data&target=[앱] 키 · 정답 · 묶음 · 문제 글`(200자 이하)을 브라우저로 연다. 앱은 서버에 쓰지 않는다. 제보는 웹과 같이 Google 로그인 후 보내며 관리자 화면에서 본다.

## 내가 정한 것 (고칠 수 있음)

- 보기로 풀기는 기본 꺼짐. 대회 준비생의 입력형 경험을 바꾸지 않으려는 것이다. 켜도 낱알은 같게 준다.
- 신고는 웹 제보 화면을 재사용한다(이메일 주소를 앱에 넣지 않고, 이미 운영 중인 관리자 화면으로 모은다). 대신 Google 로그인이 필요하다.

## 배포

웹을 배포해야 이미 설치된 앱이 새 해설 묶음을 받는다. 앱 기능(보기로 풀기·신고·같은 낱말 막기)은 앱 업데이트가 필요하다.
