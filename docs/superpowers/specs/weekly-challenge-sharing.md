# 주간 도전과 결과 공유 후속 설계

첫 범위는 계정과 서버 없이 같은 도전을 풀고 결과를 공유하는 것이다. 친구 목록·초대 수락·자동 순위표·검증된 경쟁은 별도의 서버 프로젝트로 둔다. 공통 게임 루프의 재방문 효과를 관찰한 뒤 이 설계의 구현 계획을 확정한다.

## 도전 식별과 공정한 비교

주간 식별자는 기기 현지 날짜에서 구한 월요일 시작 날짜로 한다. 도전 식별에는 주간 날짜뿐 아니라 실제 문항 key 목록·보기 순서·문제 묶음 버전·규칙 버전이 들어가야 한다. 로컬 묶음이 다른 두 사용자는 같은 주차여도 같은 문제라고 보장하지 않는다.

현재 일일 도전 공유에 추가한 묶음·규칙 표시는 이 구분의 첫 단계다. 실제 동일성을 검증하려면 후속 구현에서 문항과 보기 순서의 안정적인 지문을 포함해야 한다. 공통 manifest를 서버에서 배포하기 전에는 동일 식별자를 가진 로컬 결과끼리만 비교한다. 수동으로 바꾼 기기 날짜나 점수의 진위를 보장하지 않는다.

문제 수는 5개, 입력 방식은 도전에 고정하며 개인화·보기 설정을 제외한다. 속도보다 최초 독립 정답 수를 우선하고, 배정 문항 전체를 마친 결과만 완료로 공유한다. 점수는 정답 수·문항 수·시간 초과 수를 함께 기록하며 입력 답이나 문제 원문은 넣지 않는다.

## 중단과 주차 변경

진행 중 도전은 시작 주차의 문제와 규칙으로 복구한다. 주차가 넘어가도 이전 완료가 이번 주 결과를 덮지 않는다. 완료 영수증은 주차와 세션 식별자로 중복 적용을 막고, 일일 미션과 낱알은 공통 활동 규칙을 따른다. 이미 완료한 주간 도전은 공유만 가능하다.

## 서버 프로젝트의 선행 결정

자동 친구 비교를 원할 때 계정 또는 초대 코드의 소유권, 친구 관계·점수 보존 기간·삭제, 공통 manifest 버전, 오프라인 제출 정책, 중복 제출·재플레이·기기 시각 조작 대응, 신고·차단과 운영 비용을 별도 설계한다. 이 결정 전에는 계정·서버 쓰기가 없는 현재 앱의 필수 의존성으로 만들지 않는다.

후속 인수 조건은 서로 다른 묶음·규칙·보기 순서의 비교 거부, 이전 주 세션 복구, 중복 제출, 미완료 공유 제한, 공유 취소·오프라인 상태, 공개하는 정보의 최소화다. 스피드 도전은 별도 모드로 검토하며 시간 보상을 일반 학습 보상에 다시 섞지 않는다.
