# 우리말 곳간 앱(Android) 설계

작성일: 2026-11-19 · 상태: 승인 대기

## 1. 의도와 이유

웹사이트(https://woorimal-contest.co.kr, 저장소 `woorimal_contest`)가 가진 낱말·문제 데이터를 바탕으로, **Android에 맞춘 별도 서비스**를 새로 만든다. 웹을 감싸는 앱이 아니라, 짧게 자주 여는 휴대폰 사용에 맞춘 **숏폼 퀴즈 게임**이다. 웹은 지금처럼 따로 운영한다.

주요 사용자:

- **대회 준비생**: 우리말 겨루기 같은 대회를 준비하며 많이, 꾸준히 푸는 사람
- **출퇴근 사용자**: 지하철 한두 정거장 사이에 한 판을 끝내는 사람

성공의 모습: 한 판이 1~2분이면 끝나고, 끝나면 "한 판 더"를 누르게 되며, 캐릭터·곳간이 자라는 것을 보며 다음 날 다시 연다. 대회 준비생은 유형별 정답률로 실력이 느는 것을 확인한다.

## 2. 목표 · 비목표 · 실패 조건

목표

- 시간제한·하트·연속 정답이 있는 10문제 한 판
- 정답률과 캐릭터(다람쥐)·곳간 성장이 보이는 경험
- 인터넷 없이 즉시 플레이(오프라인 우선)
- 앱 업데이트 없이 문제 묶음 교체(특히 KBS 기반 문제를 일괄 제외·교체)

비목표(1차 출시에서 하지 않음)

- 계정·로그인·클라우드 동기화, 순위표·친구 비교 (나중에 붙일 수 있게만 설계)
- 방송 회차 단위 화면(회차 목록, 회차별 모의 평가)
- 십자말풀이, 낱말 카드 암기 화면
- iOS 출시 (기술은 가능하게 고르되 1차는 Android만)

실패 조건(기술적으로 돌아가도 실패)

- 한 판이 길거나 대기·로딩이 있어 숏폼 느낌이 깨짐
- 하트·충전 대기로 많이 풀고 싶은 사람을 막음
- 재미만 있고 틀린 문제를 다시 보지 못해 실력이 늘지 않음
- KBS 문제를 앱 업데이트 없이는 뺄 수 없음

## 3. 제약

- 방송 회차를 앱에 회차 단위로 넣지 않는다. 방송 문제는 **원문 그대로** 문제 은행에 섞어 쓰고, 모든 문제에 출처 라벨을 단다(`source: "kbs"` / `"original"` 등). 라벨은 관리용(일괄 제외·교체)이다.
- 콘텐츠 원본은 계속 `woorimal_contest/data/*.json`이다. 앱 저장소에서 원본을 고치지 않는다. `data/episodes/`는 사람이 승인한 회차이며 이 작업도 쓰지 않는다.
- 비밀 값(`STDICT_API_KEY`, Firebase 설정)은 앱에 넣지 않는다. 1차 앱은 서버 쓰기가 없다.
- 데이터 규모: 원본 합계 약 2.2MB. 낱말 734, 띄어쓰기 322, 맞춤법·속담 소수, 자체 콘텐츠(`original-content.json`), 방송 회차 136개·문항 약 5,100개(첫소리·주제어·단어 고르기·띄어쓰기 등, 단계 제목 표기가 제각각).

## 4. 접근 방법 (검토한 것)

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| **React Native + Expo (TypeScript)** ← 선택 | 웹의 순수 JS 로직(`grading.mjs`, `quiz.mjs`, `quiz-growth.mjs`, `mock.mjs`의 보기 생성 등) 재사용, 나중에 iOS 동일 코드, Reanimated·Lottie로 성장 연출 | 순수 Android보다 앱 용량이 조금 큼 |
| Kotlin + Jetpack Compose | Android에서 가장 매끄럽고 가벼움 | 로직 전부 재작성, iOS는 처음부터 |
| Flutter | 게임형 연출에 강함, iOS 동일 코드 | 기존 코드 재사용 불가, 새 언어 |

뺀 방법: 웹을 감싸는 TWA·웹뷰(별도 서비스라는 목표와 맞지 않음), Unity 등 게임 엔진(퀴즈 앱에는 과함).

사용자 결정: **React Native + Expo**, 새 저장소 `https://github.com/Riche3488/woorimal-app`(로컬 `D:\projects\woorimal_app`).

## 5. 결정된 설계

### 5.1 게임 방향: "곳간 키우기 + 하트 긴장감" (사용자 승인)

- 맞히면 **낱알**이 쌓이고 경험치가 오른다. 레벨업 때 다람쥐가 자라고, 일정 레벨마다 곳간이 초가 → 기와 → 큰 곳간으로 커진다.
- 한 판에 **하트 3개**. 오답·시간 초과마다 하나씩 잃고, 0이 되면 판이 끝난다.
- 하트가 다 떨어지면 **그 판만 끝나고 바로 새 판**을 시작할 수 있다. 충전 대기는 없다(사용자 승인). 재방문 유도는 연속 기록(🔥 N일)과 성장에 맡긴다.

### 5.2 한 판의 흐름 (사용자 승인)

```
[홈]   다람쥐 Lv · 곳간 단계 · 🔥 연속 일수
       [▶ 한 판 시작]   [오늘 틀린 문제 다시 풀기]
[게임] ❤️×3 · 남은 시간 바 · 진행 n/10
       정답 → 낱알 +기본, 빠를수록 보너스, 연속 정답 배수
       오답·시간 초과 → ❤️−1, 정답과 짧은 해설 잠깐 노출
[결과] 정답 수/정답률 · 얻은 낱알 · 경험치 바 · 레벨업 연출
       [다음 판]  [틀린 문제 보기]
[기록] 유형별 정답률, 약한 유형, 누적 플레이·연속 기록
```

- 문제 방식: 데이터에 보기가 있는 문제(맞춤법, 단어 고르기, OX 등)는 보기를 탭한다. **입력형 문제(첫소리·주제어·뜻 보고 낱말 등)는 실제 대회처럼 직접 입력한다**(사용자 결정). 화면이 열리면 입력창에 바로 포커스가 가고 키보드가 올라오며, 첫소리(초성)는 문제에 함께 보인다. 채점은 웹의 `normalizeAnswer`/`gradeTyped`(공백·문장부호 무시, 동의어 허용)를 따른다.
- 제한 시간은 유형별로 다르다. 보기형은 띄어쓰기 5~7초, 뜻풀이·긴 지문 10~12초. 입력형은 타이핑 시간을 고려해 20초 안팎. 최종 값은 플레이 테스트로 조정한다.
- 문제 아래에 KBS 기반 문제는 작게 **"출처: KBS 우리말 겨루기"**를 표시한다(사용자 결정). 자체 문제는 표시하지 않는다.
- 1차 출시는 **광고 없음**(사용자 결정). 판과 판 사이 광고는 다음 버전에서 검토한다.
- 출제: 처음 보는 유형은 쉬운 문제부터(웹의 `pickEasyFirst`/`EASY_FIRST_TRIES` 규칙), 틀린 문제는 다시 출제(웹의 `pickReview` 규칙)한다.

### 5.3 콘텐츠 흐름

1. `woorimal_contest`에 **앱용 문제 묶음 내보내기**(`npm run build:app-pack` 가칭)를 추가한다. 출력: 문제마다 `id`, `type`, `source`, 문제·정답·보기·해설, 난이도 표시를 담은 JSON과 `version`.
2. 묶음은 Firebase Hosting에 정적 파일로 올린다(예: `https://woorimal-contest.co.kr/app/pack.json` + 버전 파일).
3. 앱은 빌드할 때의 묶음을 내장해 첫 실행부터 오프라인으로 동작하고, 실행 시 새 버전이 있으면 내려받아 교체한다. 실패하면 기존 묶음을 계속 쓴다.
4. KBS 문제를 빼야 할 때는 내보내기에서 `source: "kbs"`를 제외해 다시 올리면 된다. 앱에서 사라진 문제의 기록은 남겨 두되 출제하지 않는다.

### 5.4 저장

- 기기 안에만 저장(성장 상태, 문제별 기록, 연속 기록, 설정).
- 저장 형식은 나중에 계정 동기화를 붙일 수 있게 문제 `id` 기준의 이벤트/요약으로 둔다.

## 6. 빌더에게 맡기는 것 (설계자의 판단, 바꿔도 됨)

- 프로젝트 구조, 상태 관리·저장 라이브러리 선택, 테스트 도구
- 웹 로직은 복사해 TypeScript로 옮기되 함수 이름과 동작은 유지(웹 저장소 코드를 직접 import하지 않음 — 두 저장소의 배포 주기가 다름)
- 경험치·낱알 수치, 레벨 곡선, 곳간 단계 수
- 캐릭터 그림: 1차는 단순한 벡터/이모지 수준 자리 표시자로 시작하고 연출 틀부터 만든다
- 앱 이름 표기, 패키지 이름, 아이콘 초안
- 진동·효과음(설정에서 끌 수 있게)
- 방송 단계 제목(표기가 80여 가지)을 문제 유형으로 묶는 규칙. 한 문항만으로 성립하지 않는 단계(십자말풀이, 끝말잇기, 짝꿍과 번호 고르기, 우리말 단어 판 등)는 묶음에서 뺀다
- 앱 표시 이름은 "우리말 곳간"을 기본으로 한다(스토어 등록 전에 바꿀 수 있음)
